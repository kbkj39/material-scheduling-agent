# 01 需求与成功标准

## 用户与问题

内容运营需要从待处理素材中找出可用内容，识别缺失资料与规则风险，并在已有排期约束下形成可确认的草稿。审核通过、草稿保存和内容发布是不同状态，本项目只完成前两者。

## 输入与输出

输入为一个带稳定 `request_id` 的请求及素材列表。每项素材包含 `asset_id`、带时区的 `required_at`、是否为硬性要求，以及可选的 `confirmed_alternative_at`（仅表示首次请求已获得用户确认）。合成资料包含素材元数据、审核规则、候选时段和已有排期。

输出逐项给出审核状态、风险原因、原始要求、建议时段、待确认项、草稿保存状态及 ID；遇到缺失、阻断、失败或调用上限时给出明确的任务状态。Trace 记录动作、参数、工具观察和简短公开决策依据，不记录模型内部思维过程。

## 核心验收

| 场景 | 成功标准 |
| --- | --- |
| 正常排期 | 信息齐全、规则通过、时段可用，成功保存草稿并返回真实回执 |
| 素材信息缺失 | 指出缺失项并请求补充，不保存可执行排期 |
| 规则风险 | 给出命中规则与风险原因，阻止风险素材保存 |
| 时段冲突 | 查找替代时段；硬性要求未经同意不得变更，替代方案标记待确认 |
| 重复提交 | 相同幂等请求只产生一份草稿并返回原 ID；变参返回冲突 |
| 保存失败 | 明确失败且无虚假成功 ID，保留已完成的审核与查询结果 |

补充验证覆盖占用时段变更、明确确认替代时段、工具错误、调用上限及保存边界。具体可执行用例和证据以 [评估文档](03-evaluation.md) 为准。

## 范围与边界

- 使用本地合成素材、规则和排期；不接入隐私数据或真实发布系统。
- 每个已保存草稿的建议时段都作为暂占时段，其他草稿不能重复占用。
- 允许保存待确认草稿；“保存成功”不代表用户已确认替代时段，更不代表已发布。
- 当前不支持对已保存草稿追加确认、取消或修改。确认草稿的后续生命周期不属于本次核心链路。
- 仅提供 CLI。多 Agent、界面、线上部署、生产级持久化调度均不在范围内。
- 真实模型的动态决策效果与离线流程正确性分别验收；没有真实模型记录时，不宣称完成前者。
